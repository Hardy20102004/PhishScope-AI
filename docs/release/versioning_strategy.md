# Versioning & Support Strategy

## 1. Semantic Versioning
PHOENIX strictly adheres to Semantic Versioning (`MAJOR.MINOR.PATCH`).
- **MAJOR**: Incompatible API changes, significant architectural shifts, or major UI overhauls.
- **MINOR**: Backward-compatible functionality additions (e.g., new Threat Intel integrations).
- **PATCH**: Backward-compatible bug fixes and security patches.

## 2. Release Cadence
- **Feature Releases (MINOR)**: Targeted for the end of every quarter (Q1, Q2, Q3, Q4).
- **Security & Bug Fixes (PATCH)**: Released continuously as needed (weekly or bi-weekly).

## 3. Long-Term Support (LTS)
Every even-numbered MAJOR release (e.g., v2.0, v4.0) will be designated as an LTS release.
- **LTS Lifecycle**: 24 months of Active Support, followed by 12 months of Security-Only Maintenance.

## 4. End-of-Life (EOL) Policy
- Non-LTS releases will reach EOL 6 months after the release of the subsequent MINOR version.
- Customers will be notified 90 days in advance of any EOL event via the Enterprise Portal.
